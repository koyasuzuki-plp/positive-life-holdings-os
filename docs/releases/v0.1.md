> **リリース日：2026年5月29日**

> **コードネーム：Foundation**

---

## 概要

Positive Life Holdings OS v0.1 は、株式会社 Positive Life Holdings の  
AI役員会システムの最初の動作バージョンである。

「個人習慣管理ツール（PositiveLifeOS）」を起点に、  
「未来のこうやと10名のAI役員が参加する経営会議システム」へ進化した最初のリリース。

ルールベースのAI役員会・ビジョン管理・事業スコア管理・マイルストーン管理が  
すべてローカル（localStorage）で動作する完全フロントエンド実装。

## 思想面の成果

v0.1 では、コードと同時に「このOSを動かす思想」を言語化・文書化した。  
これは将来のAI実連携において、役員の人格・発言品質を左右する最も重要な資産である。

### 確立した思想ドキュメント

**Positive Life Holdings 憲法 v1.0（7条）**
- 第一条：ビジョンが最高意思決定者である
- 第二条：健康は事業の土台である
- 第三条：家族との時間は聖域である
- 第四条：AIを参謀ではなく役員として扱う
- 第五条：小さく試し、速く学ぶ
- 第六条：記録が資産になる
- 第七条：人の可能性を広げることが最大の事業価値である

**AI役員会の意思決定原則（7原則）**
1. 短期利益より長期価値
2. 健康を犠牲にしない
3. 家族との時間を守る
4. ワクワクを優先する
5. 人の可能性を広げる
6. 再現性を設計する
7. 記録してコンテンツ化する

**最終判断基準**
> 「10年後のビジョンを実現したこうやが、今日のこの判断を誇りに思えるか？」

**システムの哲学を一言で**
> 「ビジョンを生きる経営」

### v0.1 で明確になった設計原則

- **実装前に変更予定ファイル一覧を提示・承認してから着手する**
- **既存機能（今日・記録）は一切壊さない**

- `dummy.ts` は将来のOpenAI API差し替えを前提とした構造

## Ver0.2 で目指すもの

**テーマ：「ルールベースから真のAIへ」**

### 目標

> v0.1 で作った「器」に、本物のAIの知性を注ぎ込む。

現在の役員発言は `dummy.ts` の静的テンプレートで生成されている。  
v0.2 では OpenAI API を接続し、議題・コンテキストに対して  
役員が本当に「考えて発言する」体験を実現する。

### v0.2 の完了条件

- [ ] `src/app/api/board/generate/route.ts` を作成し、OpenAI API を呼び出せる
- [ ] 役員10名それぞれの `system prompt`（人格・判断軸）を設計・実装する
- [ ] `docs/constitution.md` を各役員の system prompt に注入する仕組みを作る
- [ ] ストリーミングレスポンスで発言がリアルタイムに表示される
- [ ] `OPENAI_API_KEY` を環境変数で安全に管理する
- [ ] Vercel にデプロイし、スマホから URL でアクセスできる
- [ ] 既存機能（今日・記録画面）が完全に動作している

### v0.2 の制約

- API Key は絶対にフロントに置かない（必ず Next.js API Route 経由）
- `dummy.ts` は削除せず残す（ローカル開発・コスト節約のフォールバックとして）
- 既存の localStorage データ構造は変更しない

### v0.2 で期待する変化

```
v0.1 の役員発言（ルールベース）
  「財務的観点から分析します。全事業平均スコア○/100。...」
  → テンプレートの穴埋め。毎回同じパターン。

v0.2 の役員発言（OpenAI API）
  「今日の議題『○○』を受けて、CFOとして申し上げます。
   先月のダイエット事業のスコア低下と、今日のエネルギー3を
   踏まえると、この判断を今日行うことにリスクがあります。...」
  → 議題と文脈に対して本当に考えた発言。
```

## 開発メモ

### v0.1 開発で学んだこと

1. **思想の言語化が先**：コードより先に憲法・Mission・Vision・Valueを固めたことで、  
   実装の判断基準が明確になった。これは将来のAI実連携でも生きる。

2. **既存機能の保護が重要**：「今日画面」「記録画面」は一切変更せず、  
   `board/` 配下を完全新規で追加する設計が、リスクを最小化した。

3. **ダミーでもUXは作れる**：ルールベースの発言でも、  
   「0.7秒ごとの逐次表示」「3段構成の未来のこうや」「スコアフェーズ別トーン」で  
   それらしい役員会体験が成立することを確認した。

4. **constitution.md の価値**：AIへの参照指示を含む憲法ドキュメントを  
   v0.1 段階で作成したことで、v0.2 の system prompt 設計が容易になる。
